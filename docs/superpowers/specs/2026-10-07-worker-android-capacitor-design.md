# تطبيق العامل لأندرويد (Capacitor) — المواصفات

> كتبه Cowork في 2026-10-07، ووافق عليه صاحب المشروع في المحادثة. يكمّل القرار في `docs/briefs/01-worker-pwa.md` («متاجر لاحقاً: غلّف الـ PWA بـ Capacitor وابنِه في السحابة»).

## الهدف
تطبيق العامل الحالي (`apps/worker`) يصبح تطبيق أندرويد حقيقياً يُوزَّع كملف APK، دون إعادة كتابة منطقه، ويضيف ما يحتاج تطبيقاً حقيقياً: كاميرا أصلية، مسح QR، خزنة مشفّرة للرمز السري، إبقاء الشاشة مضاءة. نسخة المتصفح الحالية تبقى تعمل كما هي.

### معايير النجاح
1. ملف APK موقَّع يُبنى في GitHub Actions دون أي أداة أندرويد على جهاز صاحب المشروع.
2. على هاتف أندرويد حقيقي: الدخول بالرمز، مناوبة كاملة مع قطع الإنترنت ثم عودته، دون ضياع أو تكرار أي عملية.
3. صورة العداد بكاميرا الهاتف، ومسح بطاقة الزبون، وتسجيل الجهاز بمسح رمز QR — تعمل كلها.
4. تحديث التطبيق بتثبيت APK أحدث فوق القديم يحفظ كل البيانات المحلية (الطابور، المناوبة، الجهاز).
5. نسخة المتصفح على Vercel لا تتغير في سلوكها، وكل الاختبارات الحالية تمر.

## خارج النطاق (لا تُبنى الآن)
الطابعة الحرارية · الإشعارات · iOS (App Store محجوب في سوريا؛ مستخدمو آيفون على المتصفح) · Google Play · تطبيق الزبون (مرحلة ثانية بنفس الطريقة) · التحديث الحي للكود دون APK · نقل الطابور من IndexedDB إلى SQLite.

## البنية

### كود واحد، هدفان للبناء
- `npm run build` (كما هو اليوم): نسخة الويب لـ Vercel مع Serwist.
- `npm run build:native`: يضبط `FUELOS_TARGET=native`، فيقوم `next.config.ts` بـ:
  - `output: "export"` و`images.unoptimized: true` و`trailingSlash: true` (كل مسار يصبح مجلداً فيه `index.html`، فلا تظهر صفحة 404 عند إعادة التحميل أو الرجوع)، والناتج في `apps/worker/out`.
  - تعطيل Serwist (لا service worker داخل التطبيق؛ الملفات كلها داخل الـ APK).
- كل صفحات العامل `"use client"` ومساراتها ثابتة. إن منع أي مسار التصدير الثابت (مثل `app/manifest.ts`) يُجعل ثابتاً أو يُستثنى في البناء الأصلي فقط.
- `next/font/google` يعمل مع التصدير الثابت (الخط يُضمَّن وقت البناء).

### Capacitor
- أحدث إصدار مستقر (Capacitor 8 وقت الكتابة): يحتاج **Node 22+** و**JDK 21** (JDK في CI فقط). على جهاز صاحب المشروع يكفي Node 22؛ إن كان أقدم يُحدَّث (تنزيل صغير).
- `apps/worker/capacitor.config.ts`: `appId: "com.fuelos.worker"` (لا يتغير بعد أول إصدار)، `appName: "FuelOS العامل"`، `webDir: "out"`.
- مجلد `apps/worker/android/` يُنشأ بـ `npx cap add android` (لا يحتاج Android SDK) ويُرفع إلى git.
- `minSdk 24` (أندرويد 7 فما فوق)، `targetSdk` حسب Capacitor.
- **إصدار WebView:** Tailwind 4 يحتاج محرك Chrome 111 فما فوق. يُضبط `android.minWebViewVersion: 111`، والهاتف ذو WebView الأقدم يرى صفحة عربية: «حدّث تطبيق Android System WebView من Google Play ثم أعد فتح التطبيق» بدل شاشة بيضاء.
- `AndroidManifest`: صلاحية `CAMERA` فقط إضافة للإنترنت، و`android:allowBackup="false"` (لا تُنسخ الجلسة والرمز السري إلى نسخ Google الاحتياطي).
- الأيقونات من `public/icons` عبر `@capacitor/assets`.

### طبقة المنصّة: `apps/worker/lib/native/`
وحدة واحدة تخفي الفرق بين الويب والتطبيق. كل دالة لها سلوك ويب يطابق ما يحدث اليوم، فلا تتغير نسخة المتصفح.

| الدالة | داخل التطبيق | في المتصفح |
|---|---|---|
| `isNative()` | `Capacitor.isNativePlatform()` | `false` |
| `takeMeterPhoto(): Promise<File \| null>` | `@capacitor/camera` (كاميرا خلفية، JPEG، جودة ~70، أقصى بُعد 1600px) ثم تحويلها إلى `File` يمر على `validatePhoto` و`uploadMeterPhoto` الحاليين دون تعديل | حقل الملف الحالي |
| `scanCode(): Promise<string \| null>` | `@capacitor-mlkit/barcode-scanning`: `scan()` إن كانت وحدة Google متاحة، وإلا `null` مع رسالة «المسح غير متاح على هذا الهاتف — اكتب الرمز» | غير متاح (يبقى الإدخال اليدوي) |
| `deviceStore.get/save/clear` | خزنة مشفّرة: `@aparajita/capacitor-secure-storage` (مجانية MIT، تدعم Capacitor 8، مفتاح AES-GCM في Android Keystore) | Dexie كما اليوم |
| `keepAwake(on)` | `@capacitor-community/keep-awake` | لا شيء |
| `onResume(cb)` | `App.addListener("resume")` | `visibilitychange` الحالي |
| زر الرجوع في أندرويد | `App.addListener("backButton")`: إن لم نكن في الصفحة الأولى → `history.back()`، وإلا `App.minimizeApp()` (لا إغلاق) | لا شيء |
| `appVersion()` | `App.getInfo()` (رقم البناء) | `null` |

القاعدة: لا يستدعي أي ملف خارج `lib/native/` إضافات Capacitor مباشرة.

### التغييرات في الشاشات
- **إعداد الجهاز `/setup`:** داخل التطبيق يظهر زر رئيسي «امسح رمز الجهاز»، ويبقى الإدخال اليدوي خياراً ثانياً. الحفظ عبر `deviceStore`. في المتصفح لا تغيير.
- **صورة العداد (فتح وإغلاق المناوبة):** داخل التطبيق زر «التقط صورة العداد» يفتح الكاميرا مباشرة. الرفع وقواعده كما هي: لا يمنع المناوبة أبداً، ومسار الصورة وقاعدة الـ 409 دون تغيير.
- **ربط زبون (S2):** زر «امسح بطاقة الزبون» بجانب الحقل، والنتيجة تذهب إلى نفس `lookupCustomerForSale`. الإدخال اليدوي يبقى.
- **أثناء المناوبة المفتوحة:** `keepAwake(true)`، وتُطفأ عند الإغلاق أو الخروج.
- **المزامنة:** `SyncRunner` يضيف `onResume` كمحفّز إضافي. كل قواعد الطابور (`fuelos-offline-sync`) دون أي تغيير.
- **الحواف:** Capacitor 8 يرسم تحت شريطي الحالة والتنقل؛ يُفعَّل إدراج المسافات عبر CSS (`--safe-area-inset-*` / `env()`) بحيث لا يختفي أي زر أو رأس تحتهما.

### owner-web: رمز QR لتسجيل الجهاز
- في تبويب «الأجهزة» (`apps/owner-web/app/(app)/settings/page.tsx`)، نافذة الرمز السري التي تظهر مرة واحدة تعرض أيضاً رمز QR بجانب النص.
- محتوى الرمز: JSON مضغوط `{"t":"fuelos-device","v":1,"id":"<device_id>","s":"<secret>"}`.
- تطبيق العامل يقبل الرمز فقط إذا كان `t` و`v` صحيحين و`s` من 64 حرفاً hex، وإلا: «هذا ليس رمز تسجيل جهاز FuelOS».
- الدالة التي تقرأ الرمز وتتحقق منه (`parseDeviceQr`) دالة نقية لها اختبارات.

## التوزيع والتحديث (بلا متجر)

### البناء في GitHub Actions
- ملف `.github/workflows/worker-android.yml`، يعمل يدوياً (`workflow_dispatch`) أو عند وسم `worker-v*`.
- الخطوات: Node 22 → `npm ci` → lint واختبارات العامل → `build:native` → `npx cap sync android` → JDK 21 → `./gradlew assembleRelease` موقَّعاً → رفع الـ APK.
- `versionCode` = رقم تشغيل GitHub (`run_number`)، و`versionName` = `1.0.<run_number>`.
- متغيرات البناء العامة (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`) من GitHub Variables؛ المفتاح المنشور عام بطبيعته.

### مفتاح التوقيع
- يُنشأ مرة واحدة (PKCS12)، **لا يُرفع إلى git أبداً**، ويُحفظ في GitHub Secrets: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
- صاحب المشروع يحتفظ بنسخة احتياطية خارج الجهاز. ضياعه يعني أن الهواتف لا تقبل تحديثاً فوق النسخة المثبّتة.

### مكان الملفات (عمل Cowork في قاعدة البيانات)
- حاوية تخزين عامة القراءة `app-releases`: الكتابة لا تتم إلا من الخادم (لا سياسات كتابة للمستخدمين). الحد 100MB، والأنواع `application/vnd.android.package-archive` و`application/json`.
- المسارات: `worker/fuelos-worker-<versionName>.apk` و`worker/latest.json`.
- `latest.json`: `{"versionCode": N, "versionName": "1.0.N", "apkUrl": "<رابط عام>", "publishedAt": "<ISO>", "notes": "<نص عربي اختياري>"}`.
- الرفع عبر Edge Function اسمها `release-upload`، تتحقق من رمز إصدار (`RELEASE_UPLOAD_TOKEN` في GitHub Secrets؛ قاعدة البيانات تحفظ بصمته SHA-256 فقط):
  - `{"action":"prepare","app":"worker","versionName":...}` تعيد رابط رفع موقَّعاً للـ APK فقط.
  - `{"action":"publish","app":"worker","versionCode":...,"versionName":...,"notes":...}` تتأكد أن الـ APK موجود ثم تكتب `latest.json` (بلا تخزين مؤقت).
  - صلاحياتها محصورة في حاوية `app-releases`.
- ملاحظة: الخطة المجانية في Supabase تسمح بحد شهري لنقل البيانات؛ APK بحجم ~10MB مقبول للبداية، ويُراجع مع زيادة المحطات.

### صفحة التحميل
- `fuelos-worker.vercel.app/download` (نسخة الويب): تقرأ `latest.json`، وتعرض زر «تحميل التطبيق»، ورمز QR للرابط، ورقم النسخة، وثلاث خطوات مصوّرة نصياً: السماح بالتثبيت من هذا المصدر → التثبيت → «لا تحذف التطبيق القديم؛ ثبّت فوقه حتى لا تضيع العمليات المحفوظة».

### تنبيه التحديث داخل التطبيق
- عند التشغيل والعودة للتطبيق (مرة كل 6 ساعات كحد أقصى، وعند وجود إنترنت فقط) يقرأ `latest.json`.
- إن كان `versionCode` أكبر من رقم البناء المثبّت: شريط غير حاجب «نسخة جديدة متوفرة» مع زر «تحديث» يفتح `apkUrl` في متصفح النظام.
- إن كانت هناك عمليات بانتظار المزامنة يُضاف: «يمكنك التحديث الآن — عملياتك المحفوظة تبقى بعد التحديث».
- لا يوجد إجبار على التحديث في هذه المرحلة. فشل القراءة لا يظهر للعامل.
- مقارنة الأرقام (`isNewer(latest, installed)`) دالة نقية لها اختبارات.

## الأخطاء والحالات
- رفض صلاحية الكاميرا: «اسمح للتطبيق باستخدام الكاميرا من الإعدادات»، والمتابعة دون صورة ممكنة دائماً.
- إلغاء الالتقاط أو المسح: لا رسالة، يبقى كل شيء كما كان.
- فشل الخزنة المشفّرة في الحفظ: نفس رسالة «تعذّر حفظ البيانات على هذا الجهاز» الحالية.
- كل رسائل الأخطاء الحالية (`FUELOS_*` → عربي) دون تغيير.

## الاختبار
- **وحدات (Node test runner الحالي):** `parseDeviceQr`، `isNewer`، والسلوك الافتراضي للويب في `lib/native` (كل دالة تعيد قيمة الويب حين `isNative()` = false).
- **CI:** lint + اختبارات العامل قبل بناء الـ APK؛ أي فشل يوقف البناء.
- **نسخة الويب:** `npm run build` و`lint` و`test` تمر، وسلوكها في المتصفح كما هو.
- **قبول يدوي على هاتف أندرويد (قائمة يتبعها صاحب المشروع):**
  1. التثبيت من صفحة التحميل.
  2. تسجيل الجهاز بمسح رمز QR من لوحة صاحب المحطة.
  3. الدخول بالرمز (حساب الاختبار).
  4. فتح مناوبة مع صورة عداد بالكاميرا.
  5. وضع الطيران → ثلاث عمليات بيع (واحدة مع مسح بطاقة زبون عند عودة الإنترنت) → إطفاء وضع الطيران → المزامنة تكتمل دون تكرار.
  6. زر الرجوع لا يغلق التطبيق، والشاشة لا تنطفئ أثناء المناوبة.
  7. إغلاق المناوبة.
  8. بناء نسخة أحدث → ظهور «نسخة جديدة متوفرة» → التثبيت فوق القديمة → البيانات باقية.

## ما يحتاجه صاحب المشروع
- هاتف أندرويد 7 أو أحدث للتجربة.
- إضافة الأسرار في GitHub (بخطوات يكتبها Claude Code بالعربية) وحفظ نسخة من مفتاح التوقيع.
- Node 22 على جهازه إن لم يكن مثبّتاً.

## تقسيم العمل
- **Cowork:** حاوية `app-releases`، وEdge Function `release-upload`، وبصمة رمز الإصدار.
- **Claude Code:** كل ما في `apps/worker` و`apps/owner-web` وملف GitHub Actions. لا ملفات في `supabase/migrations`.
